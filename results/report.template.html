01The question this asks

Almost every plant-disease project trains on PlantVillage, reports an accuracy in the high nineties, and stops there. That number is real. It is also close to meaningless.

Every PlantVillage image is a studio photograph: one detached leaf, centred in frame, on a uniform grey background, under even lighting. Train and test splits both come from that distribution — so a high test score confirms the model learned that distribution, and says nothing about whether it learned plant pathology.

The way to find out is to change the photographs but not the question. This project trains on PlantVillage and then evaluates the same model, with no fine-tuning and no adaptation, on PlantDoc: the same diseases on the same crops, photographed in real fields with cluttered backgrounds, overlapping leaves, variable light and awkward angles. All 28 PlantDoc classes map onto PlantVillage classes, so the model is being asked exactly the question it was trained to answer.

Controlling the comparison

PlantDoc covers 28 of the 39 training classes. Comparing 39-class lab accuracy against 28-class field accuracy would confound "harder images" with "different label set", so every lab figure quoted alongside a field figure is restricted to the same 28 classes. A third evaluation masks the model's output to those 28 classes, separating "predicted something that cannot occur here" from "genuinely confused between two plausible diseases".

And a control, because the alternative explanation is a bug

"The model does not generalize" and "the label mapping is broken" produce identical numbers, and this project hit exactly that bug once during development. So the same model, through the same evaluation code, was also run against an independently packaged PlantVillage derivative — different uploader, different class naming, {{VAL:control.n_samples:int}} images. It scores {{VAL:control.accuracy:pct}}. The mapping and evaluation code work; what follows is domain shift, not a defect.

02How the model was built

The classifier is an ImageNet-pretrained ResNet18 fine-tuned for 12 epochs on 38,812 PlantVillage images, with a stratified 70/15/15 train/validation/test split. Training used mixed precision, OneCycle learning-rate scheduling, AdamW, gradient clipping and label smoothing. Augmentation was deliberately aggressive — random resized crops, flips, rotation, colour jitter and random erasing — precisely because the source images are so uniform that a network will otherwise memorise their incidental regularities. The model has {{VAL:meta.parameters:int}} trainable parameters.

Checkpoints were selected on validation macro F1 rather than accuracy. PlantVillage is heavily imbalanced — about 5,000 images in the largest class against 150 in the smallest — and plain accuracy would keep choosing checkpoints that are strong on common classes and indifferent to rare ones. The reported checkpoint is epoch {{VAL:meta.best_epoch:raw}}. Total training time was {{VAL:meta.train_minutes:f1}} minutes on an RTX 4060.

03In the lab, it is nearly perfect

On the held-out PlantVillage test set the model reaches {{VAL:test.accuracy:pct}} accuracy, {{VAL:test.macro_f1:f4}} macro F1 and a Cohen's κ of {{VAL:test.cohen_kappa:f4}}. Top-5 accuracy is {{VAL:test.top5_accuracy:pct}} — across {{VAL:test.n_samples:int}} images there is not one where the correct class falls outside the model's top five guesses.

Even the weakest classes are strong. The lowest per-class F1 is 0.950, on Corn — Cercospora leaf spot, which the model occasionally confuses with Corn — Northern leaf blight. That confusion is botanically reasonable: the two produce similar elongated grey-brown lesions on the same crop, and they are genuinely hard for people too.

By every standard this project would normally apply, the work is done.

It is not "right plant, wrong disease"

The most forgiving question you can ask is which crop is in the photograph — tomato or corn or apple, ignoring the disease entirely. That is a 14-way problem with obvious visual cues: leaf shape, size, venation. In the lab the model answers it {{VAL:lab.crop_accuracy:pct}} of the time. In the field, {{VAL:field.crop_accuracy:pct}}.

So the failure is not a subtle mix-up between similar pathologies. The model frequently cannot tell what plant it is looking at.

The single most telling number

34.9% of field photographs are classified as "Background_without_leaves" — the PlantVillage class meaning there is no leaf in this image. Shown a photograph of a diseased plant growing in a field, the model's most common response is to deny that it contains a leaf at all. It has learned "leaf" to mean "a specimen isolated on a grey studio background", and a leaf attached to a living plant does not qualify.

The one metric that looks survivable isn't

Collapsing all 28 classes into a single binary — is this plant sick or healthy? — gives 74.15% in the field, which sounds usable. It isn't. 67.07% of PlantDoc images are diseased, so answering "diseased" to every single photograph scores 67.07%. The model predicts "diseased" 85.29% of the time, achieving {{VAL:field.diseased_recall:pct}} recall at {{VAL:field.diseased_precision:pct}} precision.

Seven points above a constant answer is not a working triage tool. It is a model with a heavy bias toward "diseased" that happens to be pointed at a mostly-diseased dataset.

Does restricting the output to the 28 possible classes help?

Somewhat, and revealingly. Masking the model's output so it can only choose among the 28 classes that actually occur in PlantDoc lifts accuracy from {{VAL:field.accuracy:pct}} to {{VAL:restricted.accuracy:pct}}. About six points of the error came from confidently predicting classes that could not possibly be correct — most of them Background_without_leaves.

The remaining 79% error is genuine confusion among plausible options, so constraining the label space is not a fix.

05Benchmark rank does not predict field rank

Everything above concerns one model. The obvious follow-up is whether a different architecture escapes the problem — so the original project's from-scratch CNN was trained under identical conditions: same split, same augmentation, same schedule, same twelve epochs, same macro-F1 checkpoint selection. The only differences are the architecture and the absence of ImageNet initialisation.

On the benchmark the from-scratch model wins: {{VAL:alt.test.accuracy:pct}} against {{VAL:test.accuracy:pct}}, with fewer parameters ({{VAL:alt.parameters:int}} against {{VAL:meta.parameters:int}}). On the shared 28 classes the two are indistinguishable — {{VAL:alt.lab.accuracy:f4}} against {{VAL:lab.accuracy:f4}}.

In the field they are not close at all. The pretrained model manages {{VAL:field.accuracy:pct}}; the scratch model {{VAL:alt.field.accuracy:pct}} — a {{VAL:alt.gap.relative_drop:pct1}} collapse against {{VAL:gap.relative_drop:pct1}}.

This is the practical sting in the whole experiment. It is not merely that the benchmark number is inflated; the benchmark actively misranks. Whatever ImageNet pretraining contributes does not show up in the lab score at all, and only becomes visible once the photographs change. A leaderboard built on PlantVillage would order these two models backwards.

06It does not know that it is wrong

A model that fails is manageable if it fails loudly. The dangerous failure is the confident one — and that is what happens here.

On lab images the model is well calibrated: expected calibration error is {{VAL:lab_cal.expected_calibration_error:f4}}, and of the {{VAL:lab_cal.fraction_above_90_confidence:pct1}} of predictions made with over 90% confidence, {{VAL:lab_cal.accuracy_above_90_confidence:pct1}} are correct. Confidence means what it says.

On field images calibration error rises more than tenfold to {{VAL:field_cal.expected_calibration_error:f4}}. The model still makes high-confidence claims on {{VAL:field_cal.fraction_above_90_confidence:pct1}} of photographs — and of those, only {{VAL:field_cal.accuracy_above_90_confidence:pct1}} are correct. It remains {{VAL:field_cal.mean_confidence_when_wrong:pct1}} confident, on average, on the images it gets wrong.

07What the model is actually looking at

Accuracy cannot distinguish a model that reads lesions from one that reads backdrops — both score well in the lab. Grad-CAM answers the question directly by showing which pixels the predicted class score depends on.

The quantitative version of the same observation: measuring what fraction of Grad-CAM attention mass falls in the outer border of the frame, lab images score 0.649 against 0.667 for field images, where 0.750 would mean attention spread perfectly evenly. Field attention is measurably more diffuse — the model has no centred specimen to lock onto, so its evidence smears across the frame.

08What this means

The benchmark score was never measuring disease recognition. It was measuring how well the model had learned a photographic convention.

This matters beyond one dataset, because the PlantVillage number is the number that gets cited. A 99% accuracy claim implies a tool a farmer could point at a plant. The evidence here says that tool would be wrong six times in seven, would frequently deny that it was looking at a plant at all, and would report no uncertainty while doing it.

An observation on training longer

The epoch-1 checkpoint scored 93.08% in the lab and 15.22% in the field. The final epoch-{{VAL:meta.best_epoch:raw}} checkpoint scores {{VAL:lab.accuracy:pct}} in the lab and {{VAL:field.accuracy:pct}} in the field. Eleven further epochs bought 6.5 points of benchmark accuracy and cost 0.4 points of field accuracy.

This is a single comparison and the field difference is small enough to be noise. But the direction is worth stating plainly: the additional training produced no transferable improvement whatsoever. It fit the studio distribution harder.

What would actually help

  • Train on field data. The gap is a data problem before it is a modelling problem. PlantDoc is small (2,569 images), but even a modest amount of in-the-wild data during training changes what the model can key on.
  • Report cross-dataset numbers as standard. An in-domain test split cannot detect this failure, and as §5 shows it cannot even rank two models correctly. Nothing in §2 or §3 hinted at §4.
  • Segment the leaf before classifying. Removing the background removes the shortcut, at the cost of needing segmentation labels.
  • Calibrate, and refuse to answer. An abstention threshold would convert most confident errors into "unsure" — far more useful in the field than a confident wrong diagnosis.

Limitations

PlantDoc is not a clean instrument. Its labels are noisier than PlantVillage's, some images are stock photographs rather than field captures, and its class definitions were mapped onto PlantVillage's by hand. Part of the measured gap is dataset quality rather than domain shift. But label noise cannot explain a model calling a third of the images leafless, nor crop identification falling to 28.8% — those require the model to be reading something other than the plant.

09Reproducing this

Both datasets are plain parquet files. Some Hugging Face datasets — including the most-downloaded PlantVillage mirror — ship a .py loading script that executes on your machine if you pass trust_remote_code=True. Nothing here does that; the parquet-only sources were chosen deliberately. 

python src/prepare_data.py --data-root data
python src/train.py --model resnet18 --epochs 12 --run-name resnet18_pretrained
python src/cross_eval.py --model resnet18 --run-dir results/resnet18_pretrained
python src/gradcam_report.py --model resnet18 --run-dir results/resnet18_pretrained
python src/figures.py --run-dir results/resnet18_pretrained
